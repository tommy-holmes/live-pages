What was tested

The idea under test. "Decision models" take a piece of state, a question and a lettered list of options, and return one choice with probabilities in a single forward pass, with no text generation. The pitch is that an agent loop can hand its small bounded decisions (which file to read, which tool to call) to a cheap local model and save frontier-model tokens. We tested the most direct version: let a local model rank the candidate files and compare with what the frontier agent would have chosen on its own.

Hypothesis. Consulting the local model lowers token cost without lowering accuracy. Both halves must hold. If accuracy drops, or the consult costs more than it saves, the idea fails.

How a task is built

Cases come from real git history, so the correct answer is known without anyone labelling it. For each commit: the task is the commit subject; the candidates are up to 23 files found by keyword search in the parent commit (what an agent gets from rg -l); the answer is the file(s) the commit actually changed.

Invented example, not from the data task: "Handle empty cursor in the pagination helper" candidates (alphabetical): docs/api.md src/api/orders.ts src/api/pagination.test.ts ✔ src/api/pagination.ts src/components/Table.tsx src/lib/cursor.ts … up to 23 files ✔ = changed by the commit (the answer)

Filters: the subject must not contain a changed file's name; at least one answer must be in the candidate list; 1–3 changed files; ≥4 candidates; binaries/lockfiles excluded. Up to 50 cases per repository; 216 in total; median 23 candidates and 1 correct file per case, so random chance is about 6%.

Head-to-head: who was right when they disagreed?

Does Tev1's confidence mean anything?

If a model says 90% on a pick, that pick should be right about 90% of the time. For each case the model's probability for its top real option is binned below; the tick marks where perfectly calibrated confidence would land.

In 41% of cases the single most likely answer was the added "unsure" option. The Tev1 authors themselves caution that its probabilities are model preferences rather than calibrated confidence; this is what that looks like on a real task. The relationship is not even monotonic: the 50–75% bin was right less often than the 25–50% bin.

Can confidence-gating rescue it?

The natural fix is to trust Tev1 only when it is confident and otherwise use the agent's own pick. On the 60 blind cases, drag the threshold: above it, take Tev1's answer; below it, keep the agent's.

No threshold produced an accuracy above the agent alone (best achievable: 70.0%, which is simply "never follow Tev1"). Where Tev1 was most confident the agent was already right: the confident cases are the easy ones. n = 60, so small differences are noise; the direction is what matters.

What a consult costs

Accuracy is half the hypothesis. The other half is cost, and here the structure of an agent loop matters more than the model:

The mechanism. A tool call cannot be free: the agent must emit the call, wait for the result, and take another model request to act on it. Each request re-reads the whole (cached) conversation. A consult therefore costs about one extra request, however cheap the local model is. A wrong file read costs that file's tokens plus, usually, one recovery request. So a consult only pays if it prevents more than one wrong read, on average, per use.

Assumptions are on screen; change them. Costs are in "token-equivalents" at cached-input price. This is a model of the loop, not a bill.

Advisor accuracy

Model: consult = 150 new tokens + one request. Wrong read = file tokens (606, and they persist) + one recovery request. Expected wrong reads before a right one = (1 − accuracy) ÷ accuracy. A perfect advisor can only pay off in loops with small contexts; a weak one cannot.

Why it fell short

Each explanation is tagged with how well this test supports it.

  1. The task is outside what it was trained on. partly measured Tev1 was fine-tuned on 37,840 examples of NLI, yes/no questions, banking intents, news topics, sentiment, rule-based policies, routing and research-paper categories. None resemble "which file implements this change". That a 300M embedding model matched it (26 vs 22 discordant cases, p = 0.67) suggests it added little beyond text similarity between task and path.
  2. Equal information, unequal judgement. inferred The agent also saw only file names, so the gap is not about access. The agent knows conventions (tests sit beside code, docs rarely change for a bug fix, a template goes with its route); a 4B model on bare paths mostly does not. This test cannot separate which of those matters most.
  3. Probability is not confidence. measured Accuracy was 25%, 44%, 35%, 47% and 71% across rising probability bins. Even its "STRONG" label (clear leader) was right only 61% of the time; on the 8 such cases inside the agent sample, Tev1 was right 4 times and the agent 6.
  4. Where it is sure, the agent was already right. measured Gating by confidence selects the easy cases, which the agent does not need help with.
  5. Consults are expensive in this loop shape. modelled A consult is one more request over a very large context (see the calculator).
  6. Untuned input. untested Options were bare paths. One-line descriptions of each file, or fine-tuning on the agent's own past choices, may help. Vendors report large gains from domain fine-tuning; we did not test it.

It was not uniformly bad. Tev1 was best on two repositories (an iOS app: 64% vs 46% embedding; a Python analytics engine: 48% vs 42%), tied on one, and worst on a video-template repository (14% vs 36% keyword). That spread is a reason to evaluate on your own code before trusting any benchmark, including this one.

Threats to validity

  • One agent, one annotator, n = 60. The "agent" baseline is a single model's single pass, made by the same assistant that built the cases, so it knew the answer is always among the candidates. Picks were frozen before scoring and no answers or rankings were on the sheet, but an independent replication (any other agent on the same sheet) is the right check.
  • The 60-case sample was harder for Tev1 than the rest. Tev1 scored 28% (CI 19–41) on it and 45% (CI 37–53) on the other 156 cases, so the 70 vs 28 gap may be somewhat exaggerated. Using Tev1's 40% over all 216 the gap is still ~30 points (Tev1 CI 34–47 vs agent CI 58–80), but the paired test is only valid on the 60.
  • Strict ground truth. Only files the commit changed count. Opening a neighbour first is not necessarily a mistake, so absolute accuracies are low for every method; the comparison is relative.
  • Answers are always in the list. By construction, which flatters every method relative to real life, where the right file may not be among the candidates.
  • Task text is commit subjects: terse and written after the fact. Real tasks are phrased differently.
  • Five repositories by one developer in different languages; small, with idiosyncratic naming.
  • Token economics come from one user's sessions, estimated from usage counters (not billed cost); the cached-price ratio is an assumption.
  • One model version. Tev1 is labelled experimental; newer or larger decision models may behave differently.
  • Anchoring not measured. A blind-sampling harness was built to measure how advice influences the agent, but no field data had accumulated.

Not tested, and worth testing

  • Jev (TypeSafe's hosted model, 64k context). Ollama's launch coverage reports a mean-accuracy gap of only about 3 points between Jev and Tev1 on a 13-dataset classification suite, so this task mismatch probably is not closed by Jev alone, but that is an inference, not a result.
  • Other local models (Nimble 9B, Laya 421M; Clef‑Flash does not fit this machine's RAM) and fine-tuning on the agent's own decisions.
  • Richer options (a one-line description per file) and small-context loops, where a consult is cheap.
  • The use case decision models were built for: high-volume classification and routing with no frontier model in the loop.
